# 合成投诉数据标注规则

本数据集完全虚构，仅用于数据管线和评测练习。地址均为虚构地名，邮箱仅使用 example.com；它不代表真实个人、机构或投诉。

每行必须有 id、group_id、input、output。output 必须恰有 name、address、email、question 四个键；值只能是字符串或 JSON null，绝不能写成字符串 "null"。

- name 只标注明确确认的投诉人姓名。客服、登记员、同事、联系人或身份无法判定的姓名为 null。
- address 和 email 仅抽取原文明确提供的投诉人联系信息；不得补全或猜测。
- question 是原文中连续、逐字不改的实际投诉内容，保留逗号、句号等原始标点。表扬或会议通知等没有实际投诉时为 null；不得摘要、改写。
- 未出现在原文，或身份/归属不确定的信息统一标为 null。

身份规则覆盖转述人不是投诉人、两个人名无法确定谁投诉、记录员只转发会议通知等情形。承办点的地址和邮箱属于第三方；原文明确未登记投诉人的联系信息时，这两个字段为 null。仅表扬样本可以仍有明确标为投诉人的既有登记信息，但 question 为 null。

prepare_data.py 以固定种子 42 生成 25 个模板组、每组 4 条变体。整个组只进入一个集合，固定为训练 60 条、验证 20 条、测试 20 条；manifest.json 记录该划分。全部缺失、转述人、身份无法判定和无投诉变体也必须保留所属组的模板，不能另用一个跨组共享模板。质检会归一化实体、事项及已知可选槽位，确认每组只有一个模板签名且不同组签名互斥；该检查适用于本生成器，不等于能自动识别任意真实文本中的语义近重复。

准备阶段对全部集合仅执行行结构、原文连续子串、身份归属、组隔离及可复现性检查。验证集用于开发选择；测试集不得用于训练、Prompt 选择、模型对照选择或超参数选择。

## 评测中的 null 和严格解析

四个字段的主指标都以全部样本数 N 为分母。JSON 或 schema 非法时，该行四个字段都判错。null_false_fill_rate 以 gold 为 null 的单元格数为分母；只要成功解析为对象且某字段显式非 null，即使其他字段缺失也算该格误填。null_failure_rate 在同一分母下将格式/schema 失败或误填按单元格计一次，不重复加误填。零分母返回 None（写入 JSON 为 null）。

解析保留 raw、可解析的 parsed 和错误原因。允许合法的 JSON 首尾空白，拒绝重复键、NaN/Infinity、尾随文本，以及超出有限浮点范围的数字（例如 1e999，作为解析错误），防止保留的结果产生不可序列化的无穷值。

## 局限

小规模、规则化合成数据只能验证 JSON 格式、数据处理和评测流程。它不反映真实投诉的错别字、隐私风险、行业术语、地址格式或类别分布，因此不能证明真实业务泛化能力。
